# 1.0.101 measurements

1.0.101 changes renderer-only code: the Voyage "Your Ark" R3F gallery (lazy, small covers; settled boxes skip per-frame work),
the splash 3D scene (dpr 1..1.5, 512 shadow map) and the glowing border on Browse. `electron/` is identical to 1.0.100.

## Your Ark gallery (the change under test)

Packaged-style run on the 2000-game profile, 108-box ring, every cover served as a 600x900 JPEG (the harness is offline, so
earlier runs saw bare cases only and never exercised cover loading). Same machine, same profile, before / after:

| Window | Before (all 108 covers at once) | After (lazy, 256x384, 3 at a time) |
|---|---|---|
| First 10 s after entering: frames > 33 ms | 77 | 3 |
| First 10 s: long tasks | 7 | 0 |
| Steady idle: fps / worst frame | 48.1 / 799 ms | 60.3 / 17 ms |
| Stepping boxes: frames > 33 ms | 37 | 3-5 |
| GPU process memory | 1129 MB | 533-538 MB |
| Cover images fetched on entry | 108 | 19 |

(The first window still contains one 0.5 s frame: creating the WebGL context and compiling shaders, same as before.)

## Leaks and regressions vs 1.0.99

Paired 5-cycle A/B, same machine and profile: JS heap 39.6 -> 39.5 MB, DOM nodes 3846 -> 3853, listeners 3345 -> 3345, no
process or listener growth. IPC and event-loop numbers equal within noise.

## Load noise

The host runs corporate security scanners at 30-60 % total CPU. Cold start (enter-ready) for the SAME build varied between
8 and 17 s across alternating runs (1.0.99: 17.2, 16.0, 17.2, then 8.7, 8.2 s; 1.0.101: 8.6, 16.6, 10.3, then 10.7, 9.7,
11.5 s), so the cold-start and boot event-loop budgets cannot be judged against a baseline taken on a quiet machine. No budget
was loosened. The full 10-cycle model-on scenario aborted twice at its first `back-to-browse` step under load (the step
passes when run alone: Settings -> Back works, no navigation or reload events); its last complete clean run (1.0.100) was flat
(DOM 3860 per cycle, heap flat).
